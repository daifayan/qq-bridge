## 一、说说自动生成（任务一）

### 是什么
机器人定期从**现有记录**里自己挑素材 → 让模型判断"发/不发"并写草稿 → 按 publish 开关决定真发还是只存草稿。
**不是定时发帖机**：每轮有三层"可以不发"——素材太差不发、模型判断不发、随机"懒得发"。

### 代码位置（都在 `src/bridge.js`，搜「说说自动」）
- `QZONE_POST_AUTO_FILE` = `state/qzone-post-auto.json`：配置文件（**每次现读，改了立刻生效，无需重启**）。字段：
  - `enabled`（默认 false）——总开关
  - `publish`（默认 **false**）——**真发开关**。false = dry-run，只写草稿
  - `maxPerDay`（默认 1）——每天最多发几条
  - `minGapHours`（默认 8）——两条最小间隔小时数
  - `postChance`（默认 0.6）——每轮真的去"想"的概率（剩下的轮次直接懒得想）
  - `ugcRight`（默认 1）——说说可见范围：`1` 所有人可见 / `64` 仅自己可见（**验收建议先用 64**）/ 4 好友可见
- `QZONE_POST_DRAFT_FILE` = `state/qzone-auto-draft.json`：草稿与历史记录（最多 50 条），每条带 `action`：`posted` / `draft-only` / `skipped`（含原因）/ `invalid`
- `collectQzonePostMaterial()`：素材收集。只读现有数据，**没有新建任何存储**：
  - `socialV2.conversations` 各会话最近 48h 真人消息（每会话取最后 8 条，截 60 字）
  - `recentActions`（我最近自己做过的事，前 6 条）
  - `state/qq-activity.log` 尾部的入未读流水（12 行）
  - 总量截到 60 行 / 3000 字
- `buildQzonePostPrompt()`：提示词。角色卡在前（稳定前缀吃缓存）、素材在最后。要求模型输出严格一行 `发|<正文>` 或 `不发|<一句话原因>`；正文硬要求：≤60 字、有具体事件/情绪/细节，禁止"元气满满""感恩生活"类套话。
- `askQzoneSession()`：本次从评论生成里抽出来的公共函数（带会话失效自动重建重试），说说生成和空间评论共用同一个 qq-chat-v2 会话（`state/qzone-comment.json` 的 sessionId）→ 文风和评论一致。
- `qzonePostAutoRound(force)`：跑一轮。流程：频率闸门 → 收素材（<60 字符直接不生成）→ 出草稿 → 解析 → 按 `publish` 决定存草稿还是真发。
  - 闸门一共 4 道（前 3 道管"发"，第 4 道管"想"）：① 今天已发 ≥ `maxPerDay`；② 距上次真发 < `minGapHours`；③ `postChance` 随机说这轮懒得想；④ **距上次"想过"（发过/出过草稿/明确决定不发都算）< `minGapHours`**。第 ④ 道是后加的：心跳 10 分钟一次，若不卡，dry-run 下一天会白烧上百次模型调用；顺带也更像人——不会每十分钟重新考虑一遍要不要发朋友圈。
- 真发走 `qzoneReply('发 <内容>', false)` —— **与 owner 手动「指令 空间 发 …」和 POST /api/qzone 完全同一条通道**（`callSnowLuma('send_qzone_msg')` + `auditQzone` 审计到 `state/qzone.jsonl`），没有另写发送通道。发完还会 `recordRecentAction()` 回灌给聊天大脑。
- 心跳 `qzonePostAutoTimer`：每 10 分钟看一眼；深夜 1–8 点既不生成也不发（省 token，也像人）。
- `force=true`（「跑一轮」指令）：跳过频率闸门和随机懒，**仍然尊重 publish 开关**——dry-run 下手动跑也绝不会真发。

### owner 命令（私聊）
| 命令 | 作用 |
|---|---|
| `指令 空间 说说` | 看状态 + 最近 5 条草稿/记录 |
| `指令 空间 说说 开` / `关` | 开关生成（开着也只是 dry-run 出草稿） |
| `指令 空间 说说 跑一轮` | 立刻收素材、判断发/不发（不等心跳） |
| `指令 空间 发 <内容> ｜私密` | 发一条**仅自己可见**的说说（联调验收用） |
| `指令 空间 删 <tid>` | 删掉自己空间的说说（验收后清理用） |

注意：`说说` 不带参数时显示自动生成状态；带数字（`说说 3`）仍是原来的"看最近 3 条说说"。

### 怎么开（三步）
1. QQ 私聊发 `指令 空间 说说 开` → 开始生成草稿（dry-run）。
2. 想真发：把 `state/qzone-post-auto.json` 里 `publish` 改成 `true`（每次现读，改完下一轮就生效；QQ 指令**故意**没有真发开关，防误触）。
3. 用 `指令 空间 说说 跑一轮` 可以立刻验收一轮。

> 建议首次验收时把同一文件的 `ugcRight` 设成 `64`（仅自己可见）：真走完整链路但只有你能看到，
> 看完用 `指令 空间 删 <tid>` 删掉即可。正式使用时再改回 `ugcRight: 1`。

### 已验证（2026-10-17 实测）

**① dry-run 阶段**（publish=false）
- 端到端跑通：`指令 空间 说说 跑一轮` 真的产出了草稿，并自己挑了一张收藏表情配图：
  `说说自动：草稿「还没缓过来，作业一个字没动」（配图 CB04EFA296…）（dry-run，publish=false 不真发）`
  第二次跑（配图随机）：「别说了别说了，我还没缓过来」（无配图）——说明配图是**可选**的，不是每轮都硬塞。
- 状态/开关命令实测：`说说` 输出配置 + 今日计数 + 最近记录；`说说 关` / `说说 开` 正确改写 `state/qzone-post-auto.json`。
- 频率闸门单测 6/6 通过。

**② 真发阶段**（publish=true，`ugcRight: 64` = 仅自己可见，测完已删）
- **完整链路真跑通**，一次成功：
  ```
  已发到鲸鲸空间（仅自己可见），tid 281bcfe4e436d36a9d150e00（带 1 张配图）。
  说说：「明天有人过生日，可惜我明天大概不在，今天先偷偷替他记着」
  ```
- **图片真的上传成功**——这是之前最大的未知。向 OneBot 读回原始结构确认，`images` 已变成
  Qzone 自己的照片地址 `photogzmaz.photo.store.qq.com/psc?...`（不是原始表情 URL），
  说明「收藏表情 URL → 上传 → 转存为空间照片」这条链是通的。
- 可见范围生效：读回列表显示该条带 **（私密）** 标记，别人的时间线上不会出现。

### 新增：可见范围 `ugcRight`
`state/qzone-post-auto.json` 新增 `ugcRight` 字段（现读即生效）：
- `1` = 所有人可见（默认，正式使用）
- `64` = **仅自己可见**（联调/验收专用：真上传、真建说说、走完整链路，但不打扰任何人，测完可删）
- 另支持 `4`（好友可见）、`16`/`128`（部分名单，需配 `target_uins`，本模块未用）

手动指令也支持临时私密：`指令 空间 发 <内容> ｜私密`。

### 顺带修的两个真实缺陷（排障时发现）
1. **「评论会话这一轮没正常完成：error」看不出原因**：拿到的事件 reason 只写了 `kind`，把真正的报错吞了。
   改成把 `reason.error.message` / `reason.failure.message` 一起带出来。
   现在同样的失败会显示成 `…：error（Insufficient Balance）` 这种能直接定位的样子。
2. **`selectModel` 的思考档位不匹配被误判成"provider 挂了"**：autoAdapt 给每个候选都配了
   `reasoningEffort:"low"`，但两个 `ofm/*` 免费候选**不接受该档位**，报 `does not support reasoning effort "low"`。
   原逻辑当成上游故障 → 给候选上 600s 冷却 → 每轮掉回余额不足的 `deepseek-official`。
   现在 `ensureChatModel()` 遇到这类错误会**去掉 reasoningEffort 用默认档重试一次**，且**不因此上冷却**。
   （修完日志显示 `选用 ofm/reflection/beam-free` 后直接成功。）

### 还没验证的地方
- **公开可见（ugc_right=1）的那次真发没跑过**：真发链路本身已在 `ugc_right=64`（仅自己可见）下完整验证，
  发/读回/图片转存/审计/删除全部通过；差别只在可见范围这一个参数，但「公开」这件事本身没实测过。
- 心跳自动触发（不是手动「跑一轮」）那一轮没观察过；心跳 10 分钟一次、深夜 1–8 点静默，都只有单测/读码。
- 生成质量：三次产出（两条草稿 + 一条真发）都合格——短、有具体事件、没套话；
  但样本仍少，且素材集中在同一段近期记录，**素材多样性未验证**。
- **上游余额问题没解决**：`deepseek-official/deepseek-flash` 仍是 402 余额不足，现在靠 `ofm/*` 免费档顶；
  若 OFM 也挂了，说说生成和空间评论会一起失败。这是环境问题，不是本模块能修的。
- 图片只从**自己的收藏表情**里挑（本地白名单），没有做「网上找相关配图」——见下方说明。

### 关于配图的一个取舍（重要）
需求里提到"配上相关话题的图片**或者**单纯的表情包"。本次实现的是**后半句**：只从机器人自己的
QQ 收藏表情库里挑图（`state/stickers.json`，且只认有备注/标签的）。
**没做**"上网搜一张相关的图"——原因是那需要新增图片搜索/下载/转存链路，还会引入版权与内容安全风险
（自动抓图往公开空间发，翻车成本很高）。表情包是同一个人设的一部分、来源可控、白名单校验，
更像真人发朋友圈时会做的事。若以后确实想要联网配图，建议单独做、且默认仍走「仅自己可见」验收。

## 二、更像人（任务二）

代码位置：`src/bridge.js` 搜 `像个人`（约 7753–7806 行）。全部是**代码层随机/状态注入**，不是只改提示词文案：

1. **每轮随机风格提示 `styleNudgeV2(reason)`**：从 `STYLE_NUDGES` 池里按唤醒原因随机抽一条，拼在提示词**末尾**（不破坏 prompt 前缀缓存）。池子分三类：
   - `normal`：一句话回完 / 语气词或表情就够 / 允许改口 / 别总结别每句带语气词……
   - `proactiveCheck`：可以说自己刚在干嘛 / 突然想起什么就说什么 / 没话说就安静收尾
   - `replyCheck`：没人回别硬补 / 不必每条都接
2. **稳定话题偏好 `topicBiasLine()`**：读 `state/topic-bias.json`（每次现读，改了立刻生效），把 hot/cold 话题注入为"你的口味"——来劲的话题话变多、不感兴趣的敷衍甚至不接。当前值：hot = AI、游戏、吃的、沙雕图；cold = 明星八卦、股票基金。**想改偏好直接编辑这个文件**。
3. **主动分享素材 `proactiveShareSeed()`**：proactiveCheck 唤醒时随机挑一条 `recentActions`（我最近做过的事）当分享素材——它可以说"我刚刚在干嘛"，而不是干等别人开口。
4. **稳定人格块**：`antiAiLine` 从一行扩成【反AI味】+【像个人】六行（长度起伏 / 允许改口、只回语气词、只发表情 / 不必每条都接 / 别总结），在稳定前缀里，所有唤醒都生效。

这些改动拼在 `buildWakePromptV2()`（= core + recentActions + topicBias + styleNudge + 可选分享素材），唤醒与提醒两条路径都生效。

### 没验证的地方
- 效果是概率性的（每轮随机），未做多轮真实群聊观察对比。
- `topic-bias.json` 当前内容是初始值，未与用户确认是否符合鲸鲸人设。
