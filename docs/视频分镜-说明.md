# 视频分镜（让 QQ 机器人"看"视频）

2026-10-29 加。以前群里发视频，桥接只渲染一行 `[视频]`，模型完全不知道里面是什么。
现在收到视频会自动出一张**宫格分镜图** + 一份**带时间码的清单**，两者一起塞进这一轮的上下文。

## 怎么工作

```
QQ 视频消息段（带 url）
   → safeFetchBinary 下载（SSRF 防护、大小/时限上限）
   → 调 dsh-video-storyboard 的 CLI：探测 → 扫切点 → 取帧 → 拼图 → 烧格号
   → 返回：一张 PNG（≈384 token）+ 文本清单（每格起止时间、切点数、台词）
   → 桥接把 PNG 当图片附件、清单当文字，一起放进 prompt
```

模型看到的是"这 30 秒里发生了什么、大概在第几秒"，要细节再让它自己看图片。

## 依赖

| 依赖 | 必需 | 说明 |
|---|---|---|
| `ffmpeg` + `ffprobe` | 是 | 放在 `~/.dsh/tools/ffmpeg/bin/`（插件默认搜索位），或在 PATH 上 |
| `dsh-video-storyboard` | 是 | `dsh plugin --profile web add dsh-video-storyboard` |
| ASR 服务 | 否 | 不配就只有画面，没有台词 |

本机现状（2026-10-29）：ffmpeg/ffprobe 走 npm 国内镜像拿的便携二进制（`@ffmpeg-installer/win32-x64` + `ffprobe-static`），
版本偏老（ffmpeg N-92722 / ffprobe 4.0.2），1080p 够用，4K 慢。winget 与 GitHub 在这台机器上都不通。

## 配置（config.json → video）

```json
"video": {
  "enabled": true,        // 关掉就退回 `[视频]` 占位
  "cells": 9,             // 0 = 让插件按画面密度自己决定
  "maxBytes": 41943040,   // 单视频下载上限 40MB
  "timeoutMs": 150000,    // 单次分镜总时限
  "transcript": "auto",    // off | auto（auto 会走本机 ASR 出台词）
  "keepDays": 2,          // 分镜产物保留天数（过期自动清）
  "maxTextChars": 4000    // 清单进上下文的字符上限
}
```

## 硬限制（故意的）

- **一条消息只解析第一个视频**：下载 + 抽帧是重活，连发三个能把回复拖成几分钟。
- **40MB / 150 秒**：超了就不解析，退化成一行说明文字。
- **会增加延迟**：11 秒竖屏约 3.5 秒，4K 60fps 30 秒约 70 秒（老 ffmpeg 解 4K 慢）。
- **失败不静默**：任何一步出错都会在 prompt 里留一行 `[视频N（解析失败：…）]`。

## 台词（已配好本机 ASR）

`config.video.transcript` 现在是 `auto`。本机自带一套离线转写，不花钱、不联网：

| 组件 | 位置 |
|---|---|
| 服务脚本 | `~/.dsh/asr/asr-server.py`（OpenAI 兼容 `/v1/audio/transcriptions`） |
| 独立 venv | `~/.dsh/asr/venv/`（faster-whisper 1.2.1 + ctranslate2，不污染系统 Python） |
| 模型 | `~/.dsh/asr/models/faster-whisper-small/`（small，int8 跑 CPU） |
| 启动壳 | `~/.dsh/asr/start-asr.cmd` |
| 配置 | `~/.dsh/asr.json` → `manage.start` 指向上面那个 cmd |

插件在需要转写时会**自己把服务拉起来**（冷启动约 6 秒，含模型加载），跑完空闲一段时间自己退出。
实测一段合成中文语音：`今天我们来聊一聊视频分镜,先把画面切成九格,再配上时间码。`——一字不差。

两个坑记一下：

- **PyAV 版本对不上**：faster-whisper 1.2.1 调 `av.open(..., metadata_errors="ignore")`，当前 PyAV 不认这个参数，
  直接 TypeError。所以服务端**不用**它的 `decode_audio`，改用标准库 `wave` 解 16k 单声道 WAV 再喂 numpy。
- **hf-mirror 的 xet 协议会 401**：下载模型要加 `HF_HUB_DISABLE_XET=1`；单连接只有 300KB/s，
  分 6 段并行拉能跑到 4MB/s。

想换更准的模型：把 `~/.dsh/asr/models/` 换成 `faster-whisper-medium`，改 `start-asr.cmd` 里的 `ASR_MODEL_DIR` 即可。

## 自检

```bash
npm run test:video                                  # 只做静态检查（配置/CLI/ffmpeg）
npm run test:video -- "F:/某个视频.mp4"              # 真跑一遍，产出 PNG + 清单
```

产物落在 `state/media/video/`（`state/` 在 `.gitignore` 里，不会进公开仓库）。

## 排错

- 日志关键字：`视频分镜失败`、`视频分镜完成`。
- `没找到 dsh-video-storyboard` → 插件没装或装到了别的 profile。
- `分镜进程退出码 N：…` → 多半是 ffmpeg 找不到或视频编码不认识；先手动跑
  `node ~/.dsh/profiles/web/node_modules/dsh-video-storyboard/bin/storyboard.mjs <视频> --cells 9 --out t.png` 看原始报错。
- 机器人那边"看到了图但答非所问" → 模型不支持图片输入；当前 `deepseek-flash` 支持。

## 和 DSH 自带工具的关系

插件同时给 DSH 注册了 `video_probe / video_storyboard / video_zoom / video_locate` 四个工具。
QQ agent 被 `qq-tool-restrict` 挡在白名单外（只放行 `mcp__snowluma__*` 等），所以**桥接走自己的 CLI 路径**，
不依赖 agent 能不能调工具——两边互不影响。
